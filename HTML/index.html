Werkzeuge einrichten

Für den geprüften Windows-x64-Build brauchst du das .NET-9-SDK, Python 3, Rust mit Cargo und Visual Studio 2022 mit C++-Buildtools sowie dem .NET-Framework-4.7.2-Targeting-Pack. Der erste Build kann für den NuGet-Restore eine Internetverbindung benötigen.

Starte Install-CSharpX.bat im Repository. Der Assistent zeigt fehlende Werkzeuge, fragt vor Änderungen nach und bietet nach dem Build die Installation der VSIX an. Benutze -CheckOnly für eine reine Prüfung und -BuildOnly für einen Build ohne Installation.

Set up the tools

The tested Windows x64 build requires the .NET 9 SDK, Python 3, Rust with Cargo, and Visual Studio 2022 with C++ build tools and the .NET Framework 4.7.2 targeting pack. The first NuGet restore may need internet access.

Run Install-CSharpX.bat from the repository. The wizard reports missing tools, asks before making changes, and offers to install the VSIX after building it. Use -CheckOnly to inspect prerequisites or -BuildOnly to build without installing.

准备开发工具

已验证的 Windows x64 构建需要 .NET 9 SDK、Python 3、Rust 和 Cargo，以及带有 C++ 构建工具和 .NET Framework 4.7.2 目标包的 Visual Studio 2022。首次 NuGet 还原可能需要联网。

在仓库中运行 Install-CSharpX.bat。向导会列出缺少的工具，在修改前询问，并在构建后提供 VSIX 安装选项。-CheckOnly 仅检查环境，-BuildOnly 仅检查和构建。

Подготовка инструментов

Для проверенной сборки Windows x64 нужны .NET 9 SDK, Python 3, Rust с Cargo и Visual Studio 2022 с инструментами C++ и пакетом целевой платформы .NET Framework 4.7.2. Первое восстановление NuGet может потребовать интернет.

Запустите Install-CSharpX.bat из репозитория. Мастер покажет недостающие инструменты, запросит подтверждение изменений и предложит установить VSIX. -CheckOnly проверяет требования, а -BuildOnly выполняет сборку без установки.

必要なツールを準備する

検証済みの Windows x64 ビルドには、.NET 9 SDK、Python 3、Rust と Cargo、C++ ビルドツールおよび .NET Framework 4.7.2 ターゲットパックを含む Visual Studio 2022 が必要です。最初の NuGet 復元にはネット接続が必要な場合があります。

リポジトリの Install-CSharpX.bat を実行します。ウィザードは不足を表示し、変更前に確認し、ビルド後に VSIX のインストールを案内します。確認のみは -CheckOnly、インストールせずにビルドするには -BuildOnly を使います。

개발 도구 준비

검증된 Windows x64 빌드에는 .NET 9 SDK, Python 3, Rust 및 Cargo와 C++ 빌드 도구 및 .NET Framework 4.7.2 타기팅 팩을 갖춘 Visual Studio 2022가 필요합니다. 첫 NuGet 복원에는 인터넷이 필요할 수 있습니다.

저장소에서 Install-CSharpX.bat를 실행합니다. 마법사는 누락된 도구를 표시하고 변경 전에 확인을 요청한 뒤, 빌드 후 VSIX 설치를 안내합니다. -CheckOnly는 확인만, -BuildOnly는 설치 없이 빌드까지 수행합니다.

Von der Projektdatei zur EXE

Öffne Hello.csxproj in Visual Studio 2022, wähle Debug und baue das Projekt. Mit F5 startest du den Debugger. Das Hello-Beispiel wartet auf Enter und zeigt anschließend den Namen und eine Zahl.

Für ein eigenes Projekt trägst du jede Quelldatei mit CSharpXCompile in der .csxproj ein. Mit Debug und Release bekommt das Projekt getrennte Ausgabeordner. Wenn mehrere Klassen ein statisches Main enthalten, gib unter Projekteigenschaften → CSharpX → Ausgabe das Startobjekt an.

From project file to executable

Open Hello.csxproj in Visual Studio 2022, select Debug, and build the project. Press F5 to run under the debugger. The Hello sample waits for Enter and then displays a name and a number.

In your own .csxproj, add each source as a CSharpXCompile item. Debug and Release have separate output directories. If several classes have static Main methods, select the startup object under Project Properties → CSharpX → Output.

从项目文件到可执行程序

在 Visual Studio 2022 中打开 Hello.csxproj，选择 Debug 并生成项目。按 F5 调试运行。Hello 示例等待按下 Enter，然后显示姓名和数字。

在自己的 .csxproj 中，将每个源文件添加为 CSharpXCompile 项。Debug 和 Release 的输出目录各自独立。若多个类包含静态 Main，请在项目属性的 CSharpX 输出页指定启动对象。

От файла проекта до EXE

Откройте Hello.csxproj в Visual Studio 2022, выберите Debug и соберите проект. Нажмите F5. Пример Hello ждёт нажатия Enter, после чего выводит имя и число.

В собственном .csxproj добавьте каждый исходный файл как элемент CSharpXCompile. Debug и Release используют отдельные каталоги. Если несколько классов содержат статический Main, задайте объект запуска в свойствах проекта на странице вывода CSharpX.

プロジェクトをビルドして実行する

Visual Studio 2022 で Hello.csxproj を開き、Debug を選んでビルドします。F5 でデバッグを開始します。Hello は Enter を待ち、名前と数値を表示します。

独自の .csxproj では各ファイルを CSharpXCompile 項目として追加します。Debug と Release の出力先は別です。複数のクラスに静的 Main がある場合は、プロジェクトの CSharpX 出力設定でスタートアップオブジェクトを指定します。

프로젝트를 빌드하고 실행하기

Visual Studio 2022에서 Hello.csxproj를 열고 Debug를 선택해 빌드합니다. F5를 눌러 디버깅을 시작합니다. Hello 예제는 Enter를 기다린 다음 이름과 숫자를 표시합니다.

자체 .csxproj에서는 각 소스 파일을 CSharpXCompile 항목으로 추가합니다. Debug와 Release의 출력 폴더는 다릅니다. 여러 클래스에 정적 Main이 있다면 CSharpX 출력 프로젝트 속성에서 시작 개체를 지정합니다.

<CSharpXCompile Include="Program.csx" />
<CSharpXCompile Include="Reading.csx" />
<StartupObject>Demo.App.Program</StartupObject>

Das Beispiel expressions zeigt arithmetische Ausdrücke und Ausnahmebehandlung. Für automatisierte Prüfungen führt cargo test die Compiler- und Laufzeittests aus.

Use the compiler from a terminal

Run the commands from the repository root. check validates one source file. build writes csx-out\csx-app.exe by default and can replace a previous build at that path. Use the project build for multiple source files or external imports.

The expressions example demonstrates arithmetic and exception handling. Run cargo test to execute the compiler and runtime tests.

从仓库根目录运行这些命令。check 检查单个文件。build 默认生成 csx-out\csx-app.exe，并可能覆盖该路径上的旧构建。包含多个源文件或外部导入时应构建项目。

expressions 示例演示算术和异常处理。运行 cargo test 可执行编译器测试与运行时测试。

Компилятор в терминале

Выполняйте команды из корня репозитория. check проверяет один файл. build по умолчанию создаёт csx-out\csx-app.exe и может заменить предыдущую сборку. Для нескольких исходников или внешних импортов используйте сборку проекта.

Пример expressions показывает арифметику и обработку исключений. Команда cargo test запускает тесты компилятора и выполнения.

Tupel, Namespaces und mehrere Dateien

Benannte Elemente eines Tupels greifst du über ihren Namen oder Item1, Item2 usw. ab. Mit var kannst du ein Tupel zerlegen. Im skalaren Sprachpfad werden int, string, bool und verschachtelte Tupel als Elemente unterstützt.

Das Projekt Namespaces definiert gleichnamige Klassen in getrennten Namespaces. Ein Typalias kürzt die Klasse ab, ein Namespace-Alias verkürzt ihren Qualifizierer. Das Projekt SharedClasses zeigt eine gemeinsame Basisklasse über mehrere .csx-Dateien. Generische Klassen in Namespace-Projekten und partial class bleiben offen.

Tuples, namespaces and multiple files

Access named tuple fields by name or via Item1, Item2, and so on. Use var to deconstruct a tuple. The scalar compiler supports int, string, bool, and nested tuples as elements.

The Namespaces project defines identically named classes in separate namespaces. A type alias shortens a class name, and a namespace alias shortens its qualifier. SharedClasses places a common base class in a separate .csx file. Generic classes in namespace projects and partial classes are still outside the supported subset.

元组、命名空间与多文件

可以通过名称或 Item1、Item2 等访问元组元素，也可以使用 var 解构。标量编译器支持 int、string、bool 和嵌套元组作为元素。

Namespaces 示例在不同命名空间中定义同名类。类型别名缩短类名，命名空间别名缩短限定名。SharedClasses 在独立 .csx 文件中定义共享基类。命名空间项目中的泛型类及 partial 类尚不支持。

Кортежи, пространства имён и файлы

К полям кортежа обращаются по имени или через Item1, Item2 и т. д. Для деконструкции используется var. Поддерживаются элементы int, string, bool и вложенные кортежи.

Пример Namespaces содержит одноимённые классы в разных пространствах имён. Псевдонимы сокращают имена типа или пространства. В SharedClasses базовый класс вынесен в отдельный .csx. Обобщённые классы в проектах с пространствами имён и partial class пока не поддерживаются.

タプル、名前空間、複数ファイル

タプル要素は名前または Item1、Item2 などで参照できます。var で分解できます。要素には int、string、bool、入れ子のタプルを使えます。

Namespaces は同名クラスを異なる名前空間に配置します。型や名前空間をエイリアスで短く指定できます。SharedClasses は共通の基底クラスを別の .csx に置きます。名前空間内のジェネリッククラスと partial class は現時点では未対応です。

튜플, 네임스페이스, 여러 파일

튜플의 요소 이름이나 Item1, Item2 등을 사용해 요소에 접근합니다. var로 튜플을 분해할 수 있습니다. 요소로 int, string, bool 및 중첩 튜플을 지원합니다.

Namespaces는 서로 다른 네임스페이스에 이름이 같은 클래스를 정의합니다. 형식 및 네임스페이스 별칭은 긴 이름을 줄입니다. SharedClasses는 공통 기본 클래스를 별도 .csx에 둡니다. 네임스페이스 프로젝트의 제네릭 클래스와 partial 클래스는 아직 지원하지 않습니다.

// examples/namespaces/Program.csx
using SensorReading = Demo.Sensors.Reading;
using Sim = Demo.Simulation;

// examples/tuples/Program.csx · Main
var reading = (Value: 42, Unit: "kPa");
var (value, unit) = reading;
Console.WriteLine($"{value} {unit}");

C, C# und Rust einbinden

Ein externes Projektmitglied wird durch einen Projektdateieintrag und eine using-Direktive mit Dateinamen eingebunden. Ein Alias schränkt den Aufruf auf Alias.Funktion ein. Alle externen Funktionsaufrufe gehören in einen unsafe-Block. Console.WriteLine ist eingebaut und kann außerhalb stehen.

Das Projekt MixedInterop liest Text in C und wertet ihn in C# aus. Für C# ist die unterstützte Signatur public static string Methode(string wert), für Rust pub fn name(value: &str) -> String. Der C-Import ist auf die Dateibrücke begrenzt. Der Import allgemeiner NuGet-Funktionen und Cargo-Abhängigkeiten ist noch offen.

Call C, C# and Rust

Add the external file to the project and select it with a using directive that names the file. An alias makes calls use Alias.Function. Every external call requires an unsafe block. The built-in Console.WriteLine can remain outside.

MixedInterop reads text in C and processes it in C#. The supported C# signature is public static string Method(string value), and the supported Rust signature is pub fn name(value: &str) -> String. The C importer is limited to the file bridge. General NuGet calls and Cargo dependencies remain outside this feature.

调用 C、C# 与 Rust

先将外部文件加入项目，再用带有文件名的 using 指令导入。指定别名后，以 Alias.Function 调用。外部调用均需放在 unsafe 块中。内置 Console.WriteLine 可放在块外。

MixedInterop 通过 C 读取文本，再用 C# 处理。C# 支持 public static string Method(string value)，Rust 支持 pub fn name(value: &str) -> String。C 导入仅适用于文件访问桥接。通用 NuGet 调用和 Cargo 依赖尚不支持。

Вызов C, C# и Rust

Добавьте внешний файл в проект и укажите его имя через using. С псевдонимом вызов выглядит как Alias.Function. Любой внешний вызов должен быть внутри unsafe. Встроенный Console.WriteLine можно использовать снаружи.

В MixedInterop код C читает текст, а код C# обрабатывает его. Поддерживаются сигнатуры public static string Method(string value) для C# и pub fn name(value: &str) -> String для Rust. Импорт C ограничен файловым мостом. Общие вызовы NuGet и зависимости Cargo пока не поддерживаются.

C、C#、Rust を呼び出す

外部ファイルをプロジェクトに追加し、ファイル名を含む using で選択します。別名を付けた場合は Alias.Function で参照します。外部呼び出しは unsafe 内で行います。組み込みの Console.WriteLine は外でも使えます。

MixedInterop は C でテキストを読み、C# で処理します。C# は public static string Method(string value)、Rust は pub fn name(value: &str) -> String に対応します。C はファイル用のブリッジに限られます。一般的な NuGet 呼び出しと Cargo の依存関係は未対応です。

C, C#, Rust 호출

외부 파일을 프로젝트에 추가하고 파일 이름을 지정한 using에서 선택합니다. 별칭을 사용하면 Alias.Function으로 호출합니다. 모든 외부 호출에는 unsafe 블록이 필요합니다. 기본 제공 Console.WriteLine은 블록 밖에서도 사용할 수 있습니다.

MixedInterop은 C에서 텍스트를 읽고 C#에서 처리합니다. C#은 public static string Method(string value), Rust는 pub fn name(value: &str) -> String을 지원합니다. C 가져오기는 파일 브리지로 제한됩니다. 일반 NuGet 호출과 Cargo 종속성은 아직 지원하지 않습니다.

using "c_file_access.h" as Native;
using "Summary.cs" as Managed;

public static void Main()
{
    string report = "";
    unsafe
    {
        string text = Native.csx_c_file_round_trip("report.txt");
        report = Managed.Describe(text);
    }
    Console.WriteLine(report);
}

Fehler abfangen und Fehlerstelle finden

Verwende try, catch und finally. Derzeit kann ein catch verschiedene Fehler behandeln und erhält bei einer benannten Ausnahme einen Meldungstext. Mehrere typisierte catch-Blöcke werden noch nicht unterstützt.

Prüfe bei einem Buildfehler zuerst das CSX-Kennzeichen in der Fehlerliste. CSX1709 weist auf einen externen Aufruf außerhalb von unsafe hin. CSX2105 meldet mehrere Main-Methoden ohne Auswahl. CSX2210 meldet einen mehrdeutigen Klassennamen. In unterstützten Debug-Projekten kannst du einen Haltepunkt direkt in der .csx-Datei setzen.

Handle exceptions and locate build errors

Use try, catch and finally. A catch can handle different failures, and a named exception variable holds the message text. Multiple typed catch clauses are still unavailable.

Start with the CSX code in the Visual Studio Error List. CSX1709 means an external call is outside unsafe. CSX2105 indicates multiple Main methods with no selection. CSX2210 indicates an ambiguous class name. Supported Debug projects allow breakpoints directly in .csx files.

处理异常和定位构建错误

使用 try、catch 和 finally。一个 catch 可以处理不同的失败，具名异常变量保存错误消息。目前尚不支持多个按类型匹配的 catch。

先在 Visual Studio 错误列表中查看 CSX 编号。CSX1709 表示外部调用位于 unsafe 块之外，CSX2105 表示多个 Main 未选择启动对象，CSX2210 表示类名有歧义。受支持的 Debug 项目可直接在 .csx 文件中设置断点。

Исключения и ошибки сборки

Используйте try, catch и finally. Один catch может обработать разные ошибки, а именованная переменная исключения хранит сообщение. Несколько типизированных catch пока недоступны.

Проверьте код CSX в списке ошибок Visual Studio. CSX1709 означает вызов вне unsafe, CSX2105 — несколько Main без выбора, CSX2210 — неоднозначное имя класса. В поддерживаемых проектах Debug точки останова ставятся в файлах .csx.

例外処理とビルドエラー

try、catch、finally を使います。ひとつの catch で異なるエラーを処理でき、名前付き例外変数にはメッセージが入ります。複数の型付き catch は未対応です。

Visual Studio のエラー一覧で CSX 番号を確認します。CSX1709 は unsafe 外の外部呼び出し、CSX2105 は Main が複数あり選択なし、CSX2210 はクラス名の曖昧さを示します。対応する Debug プロジェクトでは .csx に直接ブレークポイントを置けます。

예외 처리와 빌드 오류 찾기

try, catch, finally를 사용합니다. catch 하나로 서로 다른 오류를 처리할 수 있고 예외 변수에 메시지가 들어갑니다. 예외 형식별로 여러 catch를 두는 기능은 아직 지원하지 않습니다.

Visual Studio 오류 목록에서 CSX 코드를 확인합니다. CSX1709는 unsafe 밖 외부 호출, CSX2105는 시작 개체 선택 없이 Main이 여러 개인 경우, CSX2210은 클래스 이름의 모호함을 뜻합니다. 지원되는 Debug 프로젝트에서는 .csx에 중단점을 설정할 수 있습니다.

try
{
    int value = 1 / 0;
}
catch (Exception error)
{
    Console.WriteLine(error);
}
finally
{
    Console.WriteLine("cleanup");
}

Package a build and troubleshoot

With C# imports, the default build produces an executable and a .managed directory. The single-file option embeds those managed files into the EXE or DLL. Bundling .NET itself is a separate, off-by-default option for Windows x64.

If setup or build fails, run Install-CSharpX.bat -CheckOnly and inspect target\install-build.log and target\install-build-errors.log. Linux and macOS targets require matching toolchains. The example workflow here was tested on Windows x64.

打包和排查问题

导入 C# 时，默认生成 EXE 与 .managed 目录。单文件选项将这些托管文件嵌入 EXE 或 DLL。Windows x64 可另行启用嵌入 .NET 运行时，默认关闭。

安装或构建失败时，运行 Install-CSharpX.bat -CheckOnly，并查看 target\install-build.log 与 target\install-build-errors.log。Linux 和 macOS 目标需要对应工具链。本指南的示例流程已在 Windows x64 上验证。

Упаковка и диагностика

При импорте C# обычная сборка создаёт EXE и каталог .managed. Параметр единого файла встраивает эти файлы в EXE или DLL. Встраивание среды .NET — отдельный параметр для Windows x64, выключенный по умолчанию.

При сбое запустите Install-CSharpX.bat -CheckOnly и проверьте журналы target\install-build.log и target\install-build-errors.log. Для Linux и macOS нужны подходящие инструменты. Описанные примеры проверены в Windows x64.

配布とトラブル対処

C# インポートを使うと、既定では EXE と .managed ディレクトリが生成されます。単一ファイル設定でこれらを EXE または DLL に埋め込めます。Windows x64 の .NET ランタイム同梱は別設定で、既定ではオフです。

失敗時は Install-CSharpX.bat -CheckOnly と target\install-build.log、target\install-build-errors.log を確認します。Linux と macOS には対象に合ったツールチェーンが必要です。ここで紹介した手順は Windows x64 で検証済みです。

배포 및 문제 해결

C#을 가져오는 빌드는 기본적으로 EXE와 .managed 폴더를 생성합니다. 단일 파일 옵션은 이 파일들을 EXE 또는 DLL에 포함합니다. Windows x64의 .NET 런타임 포함은 별도 옵션이며 기본적으로 꺼져 있습니다.

설치나 빌드가 실패하면 Install-CSharpX.bat -CheckOnly를 실행하고 target\install-build.log와 target\install-build-errors.log를 확인합니다. Linux와 macOS에는 대상에 맞는 도구 체인이 필요합니다. 이 안내의 예제는 Windows x64에서 검증했습니다.

<PropertyGroup>
  <CSharpXBundleManaged>true</CSharpXBundleManaged>
  <CSharpXBundleDotNet>false</CSharpXBundleDotNet>
</PropertyGroup>
